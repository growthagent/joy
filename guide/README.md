# Joy Guide

A guide to building and structuring web apps with Joy, kept here so it is
not lost. It is a starting point, not a finished text.

The guide is one page of HTML, generated by `build.roc`. The topics are
written in Roc with joy-html, and the build renders them, the index and the
pager links into `page.html`, colouring the Roc code with roc-parser's Roc
lexer. The address's `#anchor` picks the topic on screen, which the
stylesheet does on its own. A short script in the page does the rest: it
marks the topic in the index and names it in the tab, filters the index by
a word, opens it on a phone, pages through the topics with the arrow keys
and makes the Copy buttons copy. To read it from a checkout, build and
serve it:

```sh
cd guide
./build.roc
caddy file-server --root www --listen 127.0.0.1:8000
```

It is also the landing page of Joy's GitHub Pages site. The Deploy docs
workflow builds it, publishes `www/` at the root and replaces
`LATESTVERSION` in `www/index.html` with the newest release that has docs,
so the API docs links point at that release and at the main branch. Served
from a checkout, those links lead nowhere.

## Where things are

- `page.html` is the page around the guide, with its script.
- `Topics.roc` lists the topics in reading order with what the index shows
  of each, and `Guide.roc` finds a topic's body.
- `Topic/` holds one module per topic, its text written with joy-html.
- `Doc.roc` makes the code blocks, with their file names and Copy buttons,
  and `Highlight.roc` colours them.
- `Index.roc` makes the index and the phone's bar above it.
- `Page.roc` renders the index and the topics into `page.html`, which
  `build.roc` writes to `www/index.html`.
- `www/` holds the stylesheet beside the page the build writes.

A new topic is a tag in `Topics.Topic`, its row in `Topics.info`, a module
in `Topic/` and its row in `Guide.body`. The compiler points out the rows
still missing.

## What it covers

Four parts, 24 topics:

- **Start here**: what Joy is, a first app, the update loop, views,
  effects, subscriptions and flags.
- **Growing an app**: pages, the three folders (shared, client, server),
  server rendering and hydration, bundles, one type for every URL, the
  routing table and typed endpoints.
- **Structuring for scale**: picking the simplest API, partials, pieces
  with their own state, state as types, narrow types, messages as facts and
  organizing modules.
- **Reference**: adding a page, the `./joy` command and further reading.

The examples assume the `examples/fullstack` app (Shelf, a small lending
library) and the bundle loader described in the Bundles topic. Where the
guide and the code in this repository disagree, the code is right and the
guide needs updating.

One exception: what the guide says about `./joy`, in The ./joy command and
wherever else it comes up, follows a design that is only partly built.
There the guide is ahead of the code.
